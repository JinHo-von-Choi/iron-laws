# 반례 접수와 처리

오탐·미탐 반례는 GitHub 이슈의 "반례 제보" 양식으로 받습니다.

## 처리 순서

1. 재현: 제보 코드를 그대로 점검해 같은 판정이 나오는지 확인합니다. 재현되지 않으면 버전·설정을 묻고 닫습니다.
2. 판정: 기대 판정이 맞는지 규칙의 근거(행안부 항목·CWE)와 대조합니다. 기대가 틀렸으면 이유를 남기고 닫습니다.
3. 고정: 반례를 `tests/counterexamples/<CE-번호>/`에 넣습니다. `case.yml`에 규칙·기대 판정(`flagged` 또는 `clean`)·이슈 주소를 적고 코드 파일을 둡니다. 고치기 전에는 이 사례 시험이 실패해야 합니다.
4. 수정: 엔진·규칙을 고쳐 사례 시험과 기존 시험이 모두 통과하게 합니다.
5. 기록: CHANGELOG의 Fixed에 반례 번호와 바뀐 판정을 적고 이슈를 닫습니다.

## 사례 형식

```yaml
# tests/counterexamples/CE-0001/case.yml
rule: IL-504
expected: clean        # flagged: 확정 지적이 나와야 함 / clean: 이 규칙의 확정 지적이 없어야 함
file: app.py
line: 6                # flagged일 때 지적이 나와야 하는 줄(선택)
issue: ""              # 이슈 주소
note: 셸을 거치지 않는 인자 배열 호출
```
