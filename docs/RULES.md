### 근거 표기

- 행안부 SW 개발보안 가이드 항목에 대응하는 규칙에는 항목 번호를 붙입니다.
- OWASP Top 10:2025, OWASP 에이전트 Top 10 2026, CWE Top 25 2025, 국가정보원 AI보안 가이드북(2025)의 대응 항목은 보고서의 `standards`와 `iron-laws coverage --standard`로 봅니다. 대응표의 판본이 바뀌면 다시 확인할 때까지 `미확인`으로 표시합니다.
- 어느 기준에도 대응하지 않는 규칙은 보고서에 `오철칙 자체 품질 규칙 (참고 가이드 항목 외)`로 구분합니다.
- 49개 항목 모두에 점검 규칙이 있습니다(2-16 인증시도 제한은 IL-532). 설계단계 20개 항목도 구현 규칙과 연결해 `iron-laws coverage`와 마크다운 보고서에 보여 줍니다. 5-3, 5-4 등 일부 항목은 C/C++에만 해당합니다.
- `지적 없음`은 탑재된 규칙으로 찾지 못했다는 뜻이지 문제가 없다는 뜻이 아닙니다.

## 한계

### 입력 추적

- 외부 입력 추적은 함수 안에서 실행 순서를 따릅니다(if·반복·예외 갈래를 합쳐 판정).
- 도우미 함수는 호출 깊이 4단계까지 따라갑니다.
- 다른 파일의 함수는 Python, JavaScript/TypeScript, Java, Go, PHP에서 import·require·static 호출·주입 필드를 따라 찾습니다. 찾는 횟수에 상한이 있습니다.
- 상속·추상 메서드·리플렉션을 거치는 호출과 상한에 걸린 경로는 놓치거나, `확인 필요`·근거 장부의 "확인 못 함"으로 남습니다.
- Python 위험 모듈은 별칭(`import os as o`), 가져온 이름(`from os import system`), 변수에 담은 함수(`run = os.system`), 상수 이름의 `getattr(os, "system")`, `__import__("os")`까지 풀어 찾습니다. `getattr`의 속성 이름이 변수인 것처럼 호출 대상을 실행 중에 정하는 형태는 찾지 못하고, 근거 장부에도 나오지 않습니다.
- 정제 함수는 자기가 막는 문맥(HTML, SQL, 셸, 경로 등)에서만 인정합니다. HTML 이스케이프는 SQL 삽입을 막는 것으로 보지 않습니다.
- 허용 목록 검사나 경로 범위 검사는 위험 호출 앞의 모든 경로에서 실행되고, 검사한 값이 그대로 쓰일 때만 인정합니다. 갈래마다 다른 방식으로 검사하는 코드는 알아보지 못해 확정 지적이 남을 수 있습니다.

### 규칙별

- 성능 규칙(PERF)은 코드의 모양만 봅니다. 데이터 크기와 실제 속도는 재지 못하므로 모두 `확인 필요`입니다. 지적된 줄이 정말 큰 데이터를 도는지 직접 확인하십시오. 편집 거리 계산처럼 원래 이중 반복이 필요한 알고리즘도 지적될 수 있습니다.
- 존재하지 않는 패키지 이름은 `--package-index`로 색인을 준 경우에만 판정합니다.

### 보고서와 점검 범위

- `--build-manifest git`(또는 `tsc`·`go`·`file:<목록>`)을 주면 그 목록의 파일마다 분석했는지, 왜 빠졌는지를 보고서에 남깁니다. 사유 없이 빠진 파일은 경고로, `--require-full-coverage`를 주면 점검 실패로 알립니다.
- 보고서 모순 검사는 보고서의 구조적 모순만 잡습니다. 엔진이 처음부터 잘못 판정해 보고서 전체에 일관되게 반영한 오류는 잡지 못합니다.
- 비밀값이 든 코드 줄은 모든 보고서와 수정 지시문에서 값을 `****`로 가립니다. 규칙이 비밀로 알아보지 못한 값은 가리지 못하므로, 지시문을 외부 AI에 붙여 넣기 전에 한 번 읽어 보십시오.
- 점검 시간과 메모리는 보고서 `execution.cost`에 남습니다. 실행마다 달라지는 값이라 코드가 같은 두 보고서를 비교할 때는 제외합니다. `limits.max_wall_seconds`를 넘으면 점검을 끝까지 하지 못한 것으로 보고 통과로 치지 않습니다.
- 같은 코드를 점검해도 시간은 매번 다릅니다. 시간은 같은 장비, 같은 작업 프로세스 수에서 비율로 비교하십시오.

### 정확도

- 통과 결과만으로 배포를 승인하지 마십시오. 기존 테스트, 코드 검토, 다른 보안 점검과 함께 쓰는 보조 도구입니다.
- OWASP Benchmark(Java)의 확정 지적 점수는 SQL 삽입 +75.0%, 경로 조작 +88.7%, XSS +83.7%, 명령어 삽입 +50.8%입니다. 확정 지적의 오탐률은 XSS 5.7%와 취약 암호 23.3%를 빼면 0%입니다. 명령어 삽입은 취약 사례의 절반을 놓칩니다.
- 실제 오픈소스 CVE(CWE-Bench-Java)에서는 경로 조작의 35%를 잡았고, 명령 삽입·XSS·코드 삽입은 확정 지적으로 잡지 못했습니다.
- 측정 방법과 전체 수치는 [ACCURACY.md](ACCURACY.md)에 있습니다.
